# 本地与 GitHub 协作

## 为什么不能把密钥写进代码后交给队友

Git 历史和公开下载文件都会保留提交内容。项目使用服务端变量 MIMO_API_KEY；本地启动时隐藏输入，写入被忽略的 .dev.vars；托管版使用平台秘密变量。前端和源码包都不带 Key。已发到聊天的 Key 建议在此次联调完成后轮换。

## 本地配置

项目根目录 .dev.vars 的示例（填你自己的值）：

```env
MIMO_API_KEY="YOUR_MIMO_KEY"
MIMO_FLASH_MODEL="mimo-v2.6-flash"
MIMO_PRO_MODEL="mimo-v2.6-pro"
```

启动脚本还会生成随机 TOKEN_ENCRYPTION_KEY，用于本机渠道令牌加密。保留它，否则旧授权需重新连接。

npm run configure 只配置本机密钥；npm run local 会配置、构建、迁移数据库并启动。要修改已有密钥，直接在本机修改 .dev.vars 后重启。不要把密钥贴到网页聊天、Issue、PR、截图或提交信息中。

## 数据与账号

本地启动器只绑定127.0.0.1。启动器丢弃外部传入的 oai-* 身份头，给当前机器提供 local_owner 身份，并拒绝不匹配的 Host / Origin。它是本机单用户开发入口，不是公开注册登录系统。

数据库和原件在 .local/state，重启会保留，迁移只执行一次。不同电脑的数据独立，不自动同步。旧版其他启动器的数据不会自动迁移；替换旧版本前请先通过数据页导出，并保留原目录。

本地新工厂仅获得 development 开发权限；账单为空，不伪造已付款。有效期14天，询盘和内容配额按试用规则运行；收费版本仍需真实支付网关。

## 故障排查

- EADDRINUSE：旧进程占用了8899端口。停止旧终端，再启动新版；或设置 PORT 选择另一端口。
- 页面仍是旧版本：确认旧服务已停止，在新解压目录启动，并刷新浏览器。
- 模型无权限/401：在 .dev.vars 更新密钥，重启；确认是按量计费 sk- Key。
- 模型429：检查小米额度/限流，尊重 Retry-After，稍后重试。
- 研究中超过3分钟：页面会转为暂停，可查看错误并重试；重复刷新不会重复创建策略。
- 缺少已确认事实：先核对文员提取的草稿，不能用待确认事实生成对外策略。
- 本地请求401：请用 npm run local 或提供的启动脚本；直接启动原版 wrangler dev 不会获得本地身份。
- Windows/macOS首次依赖安装失败：核对 Node.js 版本与 npm 网络，推荐 Node.js24 LTS。
- 使用代理：启动前设置你自己的 HTTP_PROXY / HTTPS_PROXY / NO_PROXY。启动器遵循环境代理和系统 CA 配置，不关闭 TLS 校验。

## 本次修复边界

针对本机启动、MiMo真实调用、持久任务和状态展示。本次没有自动完成微信商户、Meta开发者账号或公开评委站点的外部开通。开发模式不能直接暴露公网；多人线上测试需部署带正式身份边界的服务。
