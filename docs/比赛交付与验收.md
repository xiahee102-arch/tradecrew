# 比赛交付与验收

依据用户上传的《JUNCTION CHINA 2026 人工智能赛道 Xiaomi MiMo 赛题》。该文档写明作品提交形式仍待定，请以现场组织方最终要求为准。本项目围绕中国建材工厂的外贸业务，形成“一个老板 + 七位 AI 同事”的一人公司产品。

## 比赛要求的对应证据

| 赛题要求 | 工程与可展示证据 |

## 现场顺序

1. 所有者登录，创建工厂。上传实际产品目录与报价依据，展示文员只提取有逐字证据的事实。扫描件不作为可解析文本演示。
2. 故意不传材质证明。文员列缺口；老板补充并确认事实，打开原文证明依据。
3. 回答8题。总管生成马来西亚方案：编号、A/B/C、暂无可靠数据、首批20条询盘假设，不承诺获客效果。
4. 老板确认目标。商户网关若未开通，请明确展示“支付未开通”，不能伪造真实付款。若用渠道沙箱必须对评委明确说明是测试交易，保留独立环境。
5. 配置后用 WhatsApp 测试号码 / Facebook 测试员真实发送询盘；现场展示手机收到首回。手动录入会明确标“手动录入”，不自动发送。
6. 预先设置产品价格规则，需求完整后客服交接业务员。程序计算价格，法务与财务通过，再由老板批准报价。展示低毛利阻断一次。
7. 买家确认同一版报价，老板确认订单。签约/定金/生产/尾款/物流为人工凭据记录，不伪装为资金托管。
8. 生成简报，导出全部运行记录。讲清老板决策、AI 执行、原创功能和当前局限。

## 自动化测试范围

`npm test` 使用 Node 规则测试 + Miniflare D1/R2 全栈测试。外部 MiMo、Graph、支付网关为隔离的测试夹具，不会拨打真实接口，不生成生产业务数据。

目前23项自动化测试通过，另有策略页面排队、失败重试、成功状态的React服务端渲染检查。包括邮件域名/Svix验签、原线程收发、重复邮件去重、跨域请求拒绝、订阅到期暂停、Worker资源响应、本地开发权限与重启持久化。

验证：整数价格与毛利底线；缺少老板或双钥匙拦截；24小时窗口和退订拦截；C级情报不可伪装事实；租户数据隔离；缺事实无法生成方案；上传/确认/方案/开通/客服/报价/审批/订单全链路；支付伪造签名与错金额拒绝、重复回调幂等；5次重复 Meta Webhook 只生成一条询盘。

2026-11-08已用真实MiMo Flash/Pro跑通隔离的模拟业务链路，见[本地联调更新](版本更新-本地联调.md)。微信/支付宝官方下单、Meta正式权限与手机往返、站点在国内/比赛现场的网络可达性、可视化浏览器验收仍需单独完成。不要把通过测试夹具当作上述真实服务验收。
